# Development artifact lifecycle

Development evidence and disposable execution storage have different lifetimes.
Native effect, unknown-outcome, provider-usage and terminal decisions are unchanged.

| Storage | Default bounds | Protection / cleanup |
| --- | --- | --- |
| Generated-code execution scratch | 32 tasks and 256 MiB per fixed lane; 24 hours after an interrupted owner exits; 1 GiB free-space reserve | Exclusive `.active` lease and `.retain` pins prevent pruning. Normal disposal removes scratch on success, error, cancellation and timeout. Protected excess blocks new admission. |
| Immutable compiler/dependency images | 8 content versions, 2 GiB, 7 days since use | Identity includes the complete source package and native-reference overlay. Each acquire and launch revalidates bytes and read-only state. Active leases and `.retain` pins prevent eviction. Generated code/results are not cached here. |
| Tool-free conversation intake homes | 4 homes, 512 MiB, 24 hours, 1 GiB free-space reserve | One home/client is reused between turns. After the child exits, asynchronous cleanup removes the home. Dead-owner leftovers are reclaimed on subsequent admission; live/unknown ownership remains protected. Durable routing decisions and usage stay outside these homes. Ordinary drafting homes retain their existing continuity. |
| Development JSON payloads | 8 GiB and 150,000 objects per shared store, plus 1 GiB free-space reserve | The harness stores large row batches and images as gzip objects addressed by SHA256. Receipt metadata and source bindings stay in each snapshot. Reads reconstruct and verify the exact JSON. Referenced evidence is never evicted to make space; admission fails explicitly at the budget. Expired temporary writes are removed after 24 hours; live/unknown writer leases are protected. |
| Ordinary Operator screenshot evidence | 1 GiB, 1,000 image objects, 7 days for completed supporting images | Canonical terminal/quiescent/all-usage state is required before expiry. Pending, unknown, required/authoritative and explicitly pinned images remain protected; protected excess stops new image capture. Immutable reference metadata and expiry audits remain, and missing pixels cannot verify work. |
| Temporary native review renders | 1 GiB / 1,000 generated captures, 1 GiB free-space reserve | Exact autogenerated duplicates are removed after durable image retention, including identical rechecks. Unretained failures, user-named exports and qualification pins are preserved; reaching the cap refuses another export. |
| Shared development archive | 5 GiB / 1,000 closed groups across new test batches | Verified unique history is retained, not silently evicted. The limit stops further staging/archival until served material is retired. Explicit one-time historical migration archives are separate pinned evidence. |
| New test workspace staging | 10 GiB / eight expanded workspaces per development root, 1 GiB new-work reservation and 5 GiB free-space reserve | `workflow-owned-runtime.ps1 start` checks the aggregate before copying credentials or starting processes. Managed workspaces and legacy isolated workspaces count, including paused/unknown work. Admission refuses excess; existing work is never deleted by the guard. |
| Closed test workspaces | Archive immediately after owned runtime shutdown | The common stop path calls `workflow-cleanup.mjs` for all outcomes. It reduces canonical assignment events and checks actual processes. Paused/nonterminal work, unknown effects and pending usage prevent cleanup. Eligible contents, including disposable model/link copies, are deduplicated, archived and verified before expanded copies are removed. Only explicitly selected `retention.keepResultExpanded` results and their required links stay expanded. This is a developer harness, not automatic deletion of users' working models. |

The generated-code pool is `%LOCALAPPDATA%/RevitOperator/DynamicTasks/v2`.
Older layouts are not silently collected by the new producer: historical cleanup
requires an explicit manifest and archive verification. This prevents an upgrade
from removing legacy pending work.

The public harness `json()` reader understands legacy JSON and the new lossless
artifact envelopes. Consumers must use it rather than treating a reference file
as a native payload. `collect()` and the private workflow snapshot wrapper use
the shared store by default. Payload hashes do not grant native authority,
freshness, scope completeness or a successful benchmark outcome.

The ordinary evidence store also gzip-compresses new large JSON objects. Its
content hash, byte count and legacy unique-byte telemetry still describe the
original logical evidence. Retrieval decompresses before the unchanged scope
and digest checks; existing raw objects retain their original bytes and paths.
Malformed JSON/metadata is rejected before publishing an object. Image expiry
does not change native effects, criterion decisions or canonical task history.

For reliable replay, keep the archive object index, pack files and group manifests
together. The development archive restores exact bytes and checks SHA256; it does
not fabricate deleted native receipts or rerun unknown mutations. Expired copied
credentials are intentionally excluded; replay uses the current approved local
credential profile. Qualification/source payloads and pinned fixtures need an
explicit preservation decision before expanded copies are removed.

Do not compare latency or throughput while compression, archival or other heavy
filesystem work runs concurrently. Functional storage-growth checks under that
load are not clean speed comparisons or billing measurements.

Temporary owner-context image copies are separate from durable evidence objects.
Canonical completed/complete-with-issues/verified-noop tasks may retire those
copies only after quiescence, known settled usage, no unknown/in-flight work,
no Pause, and exact task/run/generation custody. Each inline image must match an
existing evidence object by size and SHA256. Keep all non-image context, native
receipts, provider journals and original evidence; write an explicit historical
pointer, never a replacement visual proof. Skip retirement when it would grow
the context. Blocked/failed/unfinished work and a sibling `.context.retain`
qualification pin remain protected. Missing, corrupt, unsupported or inaccessible
pixels fail closed without changing task outcome or retrying a provider call.
Recheck at final context storage as well as terminal settlement. Exact storage
retries compare the original output digest and cannot restore retired copies.

Provider context should contain the current relevant reference/model crops and
focused native checks. Exact duplicate historical pixels and superseded trusted
host feedback are not useful additional evidence. Scoped independent reviewers
receive their review packet instead of the execution owner's full status dump;
all native authority, Pause, unknown-effect and usage admission still applies.
Compaction is not itself a model revision. Reuse literal retained images only
when existing delivery/scope/currentness checks admit them; refresh on missing
pixels, model changes or recovery. Do not treat opaque compaction or a path as
having supplied the precise pixels needed for a new spatial decision.
